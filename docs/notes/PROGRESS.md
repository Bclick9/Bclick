## Open gates that control the next work

- **Q-005 — P0, Open:** canonical game slug/UUID/deep-link and legacy mapping, uniqueness policy, provider DTO and `categories[]` semantics need explicit tests and an accepted decision. PR #94 added route-level coverage. The Q-005 proposal in `docs/notes/2026-10-22-Q005-catalogue-identity-decision.md` separates the provider's singular category fields from Bclick's canonical category array and specifies stable identity, deterministic collision slugs, and the legacy-alias requirement. PR #95 also adds stable-slug and category-ordering tests. Q-005 remains open: the owner must accept the decision; PR #92 has already moved Casino listing/search/pagination/detail and Sandbox demo launch onto the database-backed API. Curated legacy display cards still rely on exact title/provider matching and there is no persistent legacy-slug alias map, so URL/identity acceptance remains incomplete. Premium identity scope remains unverified, and the 3,802-vs-3,639 count difference remains unresolved.
- **Q-006 — P0, Open (partially evidenced):** `docs/notes/2026-10-22-Q006-provider-spec-review.md` now records the public WinHouse docs review alongside the pinned spec and support-supplied test vectors. Current evidence verifies the ordinary BigBang bet/win body HMAC, raw-body HMAC, and WinHouse bet/win HMAC; these are contract fixtures, not wallet-handler tests. Open items are BigBang zero-round-close, per-event header requirements, replay/conflicting payload and paired refusal vectors; WinHouse cashout/cancel/refund/out-of-order event semantics and related transaction mapping; plus recorded Owner/provider acceptance. No wallet implementation is enabled.
- **Q-010 — P0, Open:** ledger lock/concurrency and normative idempotency scope, including same/different-payload replay and posting-service tests.
- **Q-011 — P0, Open:** isolated base+WAL restore, integrity checks, independent alert evidence and measured RPO/RTO. No restore result is assumed.
- **Q-013 — P0, Open:** CSP/frame/host-header policy and staging evidence for player/admin/provider iframe flows.
- **Q-020 — P0, Open:** runtime contract evidence for each implemented route, alongside static OpenAPI checks. A CI fixture for an unimplemented or unexercised operation does not close this gate.
- **Q-009 — Owner decision accepted; implementation verification pending:** the Owner chose the providers' common TND precision: `0.01 TND = 10 millimes`, with no true third fractional digit. The Q-009 change set changes the shared money exponent to TND=2, updates wallet/API representations and examples, and adds guarded Migration 008 from DB exponent 3 to 2. The parser rejects amounts such as `12.345` instead of silently rounding them; the migration refuses if any TND ledger entry exists or any TND projected balance is non-zero. Keep the gate open until CI migration rehearsal passes and the target database's preconditions are explicitly checked; do not mix the new code with a database still configured as TND=3. Real-money routing remains blocked by Q-006, Q-010, Q-011 and other release gates.
